YOLOv12 Training Code

A step-by-step guide to setting up the environment, dataset, and training a YOLOv12 model.

Phase 1: Environment Preparation (Setup)

Before working, we must first prepare the work environment. Think of it like setting up a table and equipment before starting to cook. There are three steps: check the machine, prepare the folder, and install the equipment (library).

1.1. Check GPU Availability

A GPU is a very fast, specialized "brain" for training AI. The command below checks whether we have access to a GPU. The ! at the beginning indicates that this is a system command, not regular Python code. Simply run this cell and see if any lines contain the GPU name (e.g., Tesla T4).

!nvidia-smi

1.2. Define Work Folder (HOME)

We'll use a variable called HOME as the "address" of the folder where all data and results are stored. os.getcwd() means get current working directory = view the folder we're currently in. 

import os
HOME = os.getcwd()
print(HOME)

1.3. Install Required Libraries

Library is a collection of ready-to-use code written by others, so that we don't have to write everything from scratch. Here we install:

  • ultralytics — the main tool for using and training YOLO.
  • supervision — a helper tool for processing detection results.
  • roboflow — a tool to download datasets (images + labels) from Roboflow.

The %pip install line tells Python to install them. This only needs to be run once. 

%pip install -q "ultralytics>=8.4.0" supervision roboflow

# prevent ultralytics from tracking your activity
!yolo settings sync=False
import ultralytics
ultralytics.checks()

Phase 2: Preparing the Dataset for Fine-Tuning

Dataset is a collection of images along with annotations (labels) of object locations within the images. The model learns from this dataset.

We download the dataset from Roboflow Universe (a collection of public datasets). When the program asks for an authentication token, follow the instructions:

  1. Open the link that appears and log in to your Roboflow account.
  2. Copy the token, then paste it into the input box and press Enter.
!mkdir {HOME}/datasets
%cd {HOME}/datasets

from google.colab import userdata
import roboflow

roboflow.login()
rf = roboflow.Roboflow()

project = rf.workspace("").project("")
version = project.version()
dataset = version.download("yolov12")

Phase 3: Training the Model (Custom Training)

This is the core of this guide — where the model "learns" from the dataset. Here's an explanation of each command parameter:

  • task=detect — task type: object detection.
  • mode=train — mode: training (not prediction).
  • model=yolo12n.pt — starting model: YOLOv12 nano version (small & fast), which we will fine-tune.
  • data=.../data.yaml — path to the file that describes the dataset location.
  • epochs=20 — number of training rounds (20 times viewing the entire dataset).
  • imgsz=320 — image size used (320 × 320 pixels).
  • plots=True — automatically generate training result graphs.

Note: During training, preprocessing (resizing & normalizing images) and data augmentation (manipulating images such as rotating/ zooming to make the model more robust) are performed automatically by Ultralytics. You don't need to write them manually.

%cd {HOME}

!yolo task=detect mode=train model=yolo12n.pt data={dataset.location}/data.yaml epochs=20 imgsz=320 plots=True

Phase 4: Exporting the Model to ONNX Format

ONNX is a file format that allows the model to be used across many platforms (web, apps, other devices). We convert the .pt model to .onnx, then download it to our computer. 

!yolo export model={HOME}/runs/detect/train/weights/best.pt format=onnx imgsz=320
from google.colab import files
files.download(f'{HOME}/runs/detect/train/weights/best.onnx')

Phase 5: Checking & Downloading the Class List

Finally, we view the class list (object names) recognized by the model, then save it to a classes.json file and download it. This is useful when the model is used in other applications.

import json
from ultralytics import YOLO
from google.colab import files

model = YOLO(f'{HOME}/runs/detect/train/weights/best.pt')

class_list = list(model.names.values())

file_path = f'{HOME}/runs/detect/train/weights/classes.json'
with open(file_path, 'w') as f:
    json.dump(class_list, f, indent=4)

print(f"JSON file created at: {file_path}")

files.download(file_path)

Phase 6: Displaying the Confusion Matrix

A Confusion Matrix is a visual evaluation table that summarizes the prediction results on a classification or detection problem. It plots the true labels against the predicted labels to reveal how well the model distinguishes between different classes and identify any frequent misclassifications.

During training with plots=True, Ultralytics automatically generates and saves a confusion_matrix.png in the run directory. We use IPython.display.Image to render this chart directly within the notebook interface.

from IPython.display import Image as IPyImage

IPyImage(filename=f'{HOME}/runs/detect/train/confusion_matrix.png', width=600)

Phase 7: Validating the Model (Validation Metrics)

After training is complete, we run model validation to measure detection accuracy on the unseen validation dataset using the best saved weights (best.pt). This step outputs quantitative performance metrics including Precision, Recall, and mAP50 / mAP50-95.

Here is an overview of each validation parameter:

  • task=detect — specifies object detection mode.
  • mode=val — runs validation mode to calculate evaluation metrics.
  • model=.../best.pt — path to the best-performing checkpoint saved during training.
  • data=.../data.yaml — points to the dataset configuration file containing the validation set paths and class names.
!yolo task=detect mode=val model={HOME}/runs/detect/train/weights/best.pt data={dataset.location}/data.yaml
